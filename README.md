# Ecommerce Data Pipeline

ETL-пайплайн для обработки заказов интернет-магазина с загрузкой данных в PostgreSQL, контролем качества, транзакционной синхронизацией и мониторингом выполнения.

Проект демонстрирует полный цикл работы с данными: от получения исходного CSV-файла до формирования аналитических витрин и контроля состояния ETL-процесса.

## Технологический стек

- **Python 3.12** — реализация ETL-процесса.
- **Pandas** — обработка и очистка данных.
- **SQLAlchemy, psycopg2** — взаимодействие с PostgreSQL.
- **PostgreSQL 17** — хранение данных и аналитические витрины.
- **Docker, Docker Compose** — развёртывание базы данных.
- **Windows Task Scheduler** — автоматизация запусков.
- **Logging** — журналирование и мониторинг.

## Основные возможности

### ETL и качество данных

- Загрузка исходных данных из CSV.
- Исключение отменённых заказов и записей с некорректными суммами.
- Проверка пропусков, дубликатов и корректности значений.
- Расчёт показателей качества данных.
- Сохранение очищенных данных в CSV.
- Формирование истории проверок Data Quality.

**Метрики качества данных:**

- `Data Quality Score` — показатель технического качества исходных данных.
- `Valid Orders Rate` — доля заказов, прошедших бизнес-фильтрацию.

Эти показатели рассчитываются отдельно: технически корректная запись может быть исключена по бизнес-правилам.

### PostgreSQL и синхронизация

- UPSERT заказов по `order_id`.
- Атомарная загрузка данных с использованием транзакций.
- COMMIT при успешном выполнении и ROLLBACK при ошибках.
- Опциональная полная синхронизация через Soft Delete.
- Проверка полноты снимка данных перед деактивацией отсутствующих заказов.
- Управление режимом синхронизации через `FULL_SNAPSHOT`.

По умолчанию `FULL_SNAPSHOT=false`: отсутствующие в новом CSV заказы не деактивируются.

### Аналитические витрины

**`daily_sales`**

Ежедневная аналитика активных заказов:

- Количество заказов (`orders_count`).
- Выручка (`total_revenue`).
- Средний чек (`avg_order_value`).

**`etl_monitoring`**

Агрегированная статистика выполнения ETL:

- Количество запусков.
- Успешные и неуспешные запуски.
- Доля успешных выполнений.
- Средняя продолжительность.
- Количество загруженных строк.

**`etl_health`**

Контроль текущего состояния ETL:

- Статус последнего запуска.
- Наличие зависших процессов.
- Время последней успешной загрузки.
- Итоговый статус здоровья пайплайна.

Все три аналитические витрины реализованы как SQL-представления PostgreSQL (`VIEW`).

### Автоматизация и мониторинг

- Ежедневный запуск ETL через Windows Task Scheduler.
- Независимая проверка состояния ETL каждые 30 минут.
- Регистрация запусков в таблице `etl_run_history`.
- Обнаружение зависших запусков.
- Проверка актуальности последней успешной загрузки.
- Логирование выполнения и ошибок.
- Коды завершения мониторинга для внешних систем автоматизации.

## Быстрый запуск через Docker Compose

Инструкция предназначена для **Windows PowerShell**.

### Предварительные требования

- Python 3.12.
- Git.
- Docker Desktop с поддержкой Docker Compose.

### 1. Клонировать репозиторий

```powershell
git clone https://github.com/alexey-polyakov-da/ecommerce-data-pipeline.git
cd ecommerce-data-pipeline
```

### 2. Создать виртуальное окружение

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 3. Установить зависимости

```powershell
python -m pip install -r requirements.txt
```

### 4. Настроить переменные окружения

Создать локальный `.env` из шаблона:

```powershell
Copy-Item .env.example .env
```

Указать параметры:

```dotenv
DB_HOST=localhost
DB_PORT=5434
DB_NAME=ecommerce
DB_USER=postgres
DB_PASSWORD=your_password_here
FULL_SNAPSHOT=false
```

Заменить `your_password_here` на собственный пароль.

**Важно:** файл `.env` содержит секреты и не должен публиковаться в GitHub.

Порт `5434` используется для подключения Python к PostgreSQL с компьютера. Внутри контейнера PostgreSQL работает на порту `5432`.

### 5. Запустить PostgreSQL

```powershell
docker compose up -d
```

Docker Compose:

- Создаст контейнер PostgreSQL 17.
- Создаст отдельный том для хранения данных.
- Подключит SQL-скрипт `sql/init.sql`.
- Автоматически создаст таблицы `orders` и `etl_run_history` при первой инициализации пустой базы.

Проверить состояние контейнера:

```powershell
docker compose ps
```

Ожидаемый статус: `healthy`.

SQL-скрипт инициализации выполняется при первом создании базы с пустым томом данных, а не при каждом запуске контейнера.

### 6. Запустить ETL

```powershell
python pipeline.py
```

Пайплайн последовательно:

1. Проверяет доступность PostgreSQL.
2. Регистрирует запуск в `etl_run_history`.
3. Загружает исходный CSV.
4. Формирует отчёт Data Quality.
5. Очищает и валидирует данные.
6. Сохраняет очищенный CSV.
7. Выполняет UPSERT в PostgreSQL в рамках транзакции.
8. При разрешённой полной синхронизации обрабатывает Soft Delete.
9. Создаёт аналитические представления.
10. Обновляет историю запуска и проверяет состояние ETL.

При успешном завершении выводится:

```text
ETL-пайплайн успешно завершён!
```

### 7. Проверить данные

Выполнить:

```powershell
docker compose exec postgres psql -U postgres -d ecommerce -c "SELECT * FROM daily_sales ORDER BY order_date;"
```

Ожидаемый результат для тестового набора:

| Дата | Заказов | Выручка, ₽ | Средний чек, ₽ |
|---|---:|---:|---:|
| 2026-10-28 | 2 | 5 000 | 2 500 |
| 2026-10-30 | 1 | 3 200 | 3 200 |
| 2026-10-31 | 1 | 4 100 | 4 100 |

**Итого:**

- Корректных заказов: 4.
- Общая выручка: 12 300 ₽.
- Средний чек: 3 075 ₽.

### 8. Проверить мониторинг

```powershell
python monitor.py
```

Коды завершения:

| Код | Значение |
|---|---|
| `0` | Состояние ETL — `OK` |
| `1` | Обнаружено проблемное состояние |
| `2` | Ошибка выполнения мониторинга |

### 9. Остановить тестовую базу

```powershell
docker compose down
```

При обычной остановке данные в Docker volume сохраняются.

Для полного удаления тестовой базы вместе с томом данных:

```powershell
docker compose down -v
```

**Внимание:** параметр `-v` удаляет данные в томе Docker Compose.

## Автоматический запуск

Для локальной автоматизации на Windows используются:

- `run_pipeline.bat` — запуск основного ETL-пайплайна.
- `run_monitor.bat` — запуск независимого мониторинга.
- Windows Task Scheduler — выполнение задач по расписанию.

В тестовом окружении настроены:

- ETL — ежедневно в 09:00.
- Мониторинг — каждые 30 минут.

BAT-файлы используют локальный путь проекта и виртуальное окружение Python. При переносе проекта на другой компьютер пути необходимо адаптировать.
